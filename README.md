# Cure & RPC Pacing | Power BI Analytics Portfolio

A four-page Power BI Project (`.pbip`) demonstrating mortgage-servicing delinquency cure performance and **right-party contact (RPC)** activity. The report analyzes daily pacing against the same time last month (STLM) and the same time last year (STLY).

> **Data disclosure:** The sample datasets are generated by a seeded simulation. They are synthetic and do not represent actual borrowers, employer data, or real portfolio performance.

## Business problem

Mortgage servicing teams need timely visibility into whether delinquent loans are curing during the month, how right-party contact is progressing, and where performance differs across investor portfolios and delinquency phases.

## Dashboard pages

1. **Cure/RPC Pacing** — Cure and contact pacing overview.
2. **Cure/RPC STLM** — Same-time-last-month comparisons.
3. **Cure/RPC Month Side by Side** — Monthly performance comparisons.
4. **Cure/RPC Daily** — Daily activity and trends.

## Skills demonstrated

- **Power BI / DAX:** Measures, filter-aware calculations, monthly and daily pacing comparisons
- **Semantic modeling:** TMDL source-controlled model definitions, related fact tables and lookup tables
- **Power Query:** Parameter-based ingestion from CSV files
- **Domain analysis:** 30/60/90/120+ delinquency segmentation, loan cures, contact tracking and investor comparison

## Open in Power BI Desktop

1. Download or clone the **complete repository**.
2. Open `Cure & RPC Pacing.pbip` in Power BI Desktop.
3. Select **Home → Transform data → Edit parameters**.
4. Set `DataFolder` to the absolute path of the repository's `data` folder, then select **Close & Apply**.
5. Refresh the model to load the CSV files.

The version-controlled project does not include Power BI's local cache, so a first refresh is required.

## Regenerate sample data

```bash
python scripts/generate_sample_data.py
python scripts/generate_sample_data.py --as-of 2026-09-15 --seed 7
python scripts/validate_sample_data.py
```

By default, the sample is frozen as of April 14, 2026 for consistent report previews. When changing the `--as-of` month, update the model's hard-coded **Month Sort** table if necessary.

## Analytical model

Fact tables share a grain of **day × investor × delinquency phase × transfer ID** and track the population delinquent at the previous month-end. These include:

| Table | Purpose |
| --- | --- |
| DLQ Base | Starting delinquency population, loans still delinquent, business-day helpers |
| Cure Join | Cure events such as modifications, deferrals and roll-to-current |
| RPC Join | Daily contact counts and distinct month-to-date contacts |
| Future Cures | Scheduled cure payments and month-to-date pace |
| PreviousBDCount | Business-day alignment for comparisons |

Historical STLY files provide same-time-last-year comparisons.

**Glossary:** DLQ = delinquent; RPC = right-party contact; STLM = same time last month; STLY = same time last year; PD = payment deferral; Mods = completed modifications.

## Reproducibility and privacy

The project replaces original source connections with CSV loaders using the `DataFolder` parameter. Local `.pbi` settings and cache files are excluded by `.gitignore`. All published data should remain synthetic.
